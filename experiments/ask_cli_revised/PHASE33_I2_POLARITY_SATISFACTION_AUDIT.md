## 1. Purpose and verdict

I2 separates three axes that the current code conflates:

1. **Observation result** — what an admissible observation reports (positive finding, null finding, mention only, unknown).
2. **Requirement semantic goal** — what the requirement asks for. The v9 category requirements affected by I2 use runtime default `established_presence`.
3. **Search terminality** — whether further recovery for an unmet goal is still warranted, decided from completed search status for that obligation.

Confirmed defect (preserved Attempt-2 run). Category `implicit` for `c3#suff:implicit-explicit-coverage` is bound from p36, "…their implicit biases were slight and not significant." The binding records `negated: true`. The category role's `disqualifying_guards` is `[]`, so nothing rejects it. Consequences:

- The c3 facet reads `answered` with `covered_categories: [explicit, implicit]`.
- The c3 requirement stays `filled`, so the stop-search certificate applies and recovery is never offered for c3.
- c6 is `missing` for `implicit` only because p36 is not in c6's candidate pool (§4.6). It is not a polarity result.

## 2. Current dataflow

1. `sufficiency_mapping.map_cardinality_requirement` creates one instance per requested term and calls `_bind_role_candidates` on a term-restricted spec.
2. `_bind_role_candidates` returns on the first admissible unit whose detector matches. The detector for `explicit_category_terms` is `_match_explicit_category_term`: a case-insensitive substring match with no polarity check. The caller takes `candidates[0]`. The mapper is first-match per term.
3. `is_admissible` consults only `disqualifying_guards`. v9 category roles have `[]`, so hedged, negated and absence-statement passages are all admissible.
4. `se.recompute_instance` sets `complete` iff required roles are `filled`. A binding's existence is sufficient. `_aggregate_all_requested_categories` counts `complete`.
5. `compute_stop_search_certified` reads `state` (§11).
6. `sufficiency_recovery_targets._incomplete_instance_targets` emits targets only for roles whose binding is not `filled`. A null-filled category instance emits none.
7. `answer_plan/classify._evaluate_values` renders the verbatim sentence as `role="primary"`. Its enumeration path excludes sentences matching `negation_or_hedge`; the single-sentence path does not.
8. `answer_plan/plan._instance_bindings` keeps only `filled` bindings; `_covered_categories` counts any displayed render whose values match a binding.
9. `parent_synthesis_ledger.build_resolved_empty_outcomes` requires `is_zero_evidence_terminal`. A bound null is not genuinely empty, so it never becomes a ResolvedEmptyOutcome. This holds by accident and must be preserved deliberately.
10. `_gate_status` strips the completed-search flag unless `is_zero_evidence_terminal`. A bound null is therefore never terminal, even after its obligation completed.

## 3. Root cause

- **R1 — binding without polarity.** A literal term occurrence is treated as presence. Category polarity is never inspected, and the existing negation flags are passage-scoped (§4.1).
- **R2 — bound is not satisfied.** `complete` and `filled` mean "a binding exists" for every role, so "observed, but presence not established" cannot be expressed.
- **R3 — first-match and no null-aware terminality.** The first admissible observation per term wins, so a null that comes first hides a later positive. A null-filled instance produces no recovery target, and the terminal predicates exclude it, so neither completed search nor terminal status is represented.

## 6. Null, positive and mention classifier

Evidence is classified on the **term clause**: the clause containing the term occurrence. Clauses are split at `,`, `;`, `:`, `but`, `whereas`, `although`, `though`, `while`, `however`, `yet`. They are **not** split at `and`. Nothing crosses a sentence boundary.

**A. Local null evidence.** The term clause contains a closed negation cue N (`not`, `no`, `never`, `neither`, `nor`, `without`, `fail`/`failed`/`fails`, `lack`/`lacked`/`lacks`, `non-significant`, `nonsignificant`) and a significance-class cue E (`significant*`, `significance`, `effect(s)`, `association(s)`, `correlation(s)`, `difference(s)`, `relationship(s)`, `evidence`) within a three-token window, with N governing E. A directional verb (`increase`, `reduce`, `improve`) is not E and cannot make a null alone.

*Narrow ellipsis (the only carryover in v4).* The immediately preceding clause carries a finding predicate (B), and the immediately following contrast clause (after `but`, `whereas`, `although` or `yet`) consists of `not` plus exactly one E token with no subject noun phrase. Example: "Treatment reduced pain, but not significantly." Any other carryover is UNKNOWN.

**B. Finding or assertion predicate.** The term clause contains a closed assertion predicate, for example `observed, found, showed, shown, demonstrated, revealed, expressed, detected, reported, correlated, associated, predicted, differed, responded, exhibited, identified, produced, reduced, increased, decreased, improved, affected, influenced, altered, changed`. This list is a proposal to be verified against cross-domain synthetic cases in I2-1, and widened only with evidence.

Three rules are fixed:
- Valence tokens (`positive*`, `negative*`, `higher`, `lower`, `more`, `less`) are never B. Valence is a direction property (I3), not evidence that a finding occurred.
- Measurement-only verbs are never B: `measured`, `assessed`, `included`, `recruited`, `administered`, `collected`, `tested`, `used`, `examined`, `reviewed`, `described`.
- Absence statements are never null evidence.

**C. Procedural and mention-only.** No A and no B → `mentioned_only`. Negation without E and without B (procedural negation) → `mentioned_only`. Measurement-only sentences → `mentioned_only`.

**Classification of a term occurrence:**
- `null_finding`: A holds (same-clause, or the narrow ellipsis).
- `positive_finding`: B holds in the term clause, A does not hold, and no unresolved carryover.
- `unknown`: N in the term clause without E but with a B or directional cue (for example "did not increase X"); two or more N in the term clause; the constructions `not only`, `no less`, `not less`; a contrast carryover that does not match the narrow pattern; attachment uncertain.
- `mentioned_only`: otherwise.

Hedge is orthogonal and never changes polarity. Passage `negated`, `has_negation` and `absence_statement` are not used as null evidence. `contrary_finding` is never emitted.

Stop/go for I2-1: no positive from valence alone; no null from procedural negation; no null from an unverified carryover; every synthetic row in §16 classified as stated.

## 7. Aggregation over observations (D9)

All admissible observations per term; not first-match. One or more positive: presence satisfied; nulls are retained and disclosed, not discarded. Positive plus null is "established, with a disclosed null", not a conflict. Only nulls: null-only. Only mentioned or unknown: not established. Contrary conflict is unreachable in v4 because contrary is reserved.

## 9. Search terminality (D12: Option A, target-scoped)

**Principle.** Terminality is decided per goal-unsatisfied obligation, using the existing target search status as the authority. It is not a whole-requirement condition.

For category instance I with semantic-goal recovery target T (generic reason `semantic_goal_unsatisfied`, §10):

- T is generated because I is bound but goal-unsatisfied.
- The identity of T is content-derived (§4.8), so the same T matches across the initial and final maps.
- **If `structured_search_outcomes[R]["target_states"][T]["state"] != "completed"`:** I remains recoverable.
- **If that state is `completed` and no satisfying positive observation emerged for I:** the goal-unsatisfied obligation is terminal for this run. T is not regenerated.
- Other category instances and targets under the same requirement remain independently recoverable.
- Requirement-level completion may be derived as an aggregate of its target states, for reporting only.

**Generic search concept:** `semantic_goal_unsatisfied_terminal`, defined per target and per instance.

**Scientific answer qualifier, derived from the evidence** once the target is terminal:
- null observation → `measured_null_terminal`;
- mention-only observation → `mentioned_only_terminal`;
- unknown-only observation → `not_established`, with a terminal-search disclosure. A more specific qualifier is not justified, and no `unknown_terminal` state is invented.

Before the target completes, a null-only instance is recoverable, and the qualifier is `measured_null_only`.

**Zero-evidence behaviour is unchanged and separate.** `is_genuinely_empty`, `is_zero_evidence_terminal`, `empty_result_semantically_allowed` and `ResolvedEmptyOutcome` keep their current meaning. `build_resolved_empty_outcomes` still requires zero-evidence terminality, so a null-only requirement cannot produce a ResolvedEmptyOutcome.

**Mechanism (I2-2).** The existing `target_states` is the completion object. Terminal target identities are passed to target generation through the search status, so a terminal goal-unsatisfied target is not regenerated. No parallel terminality store is introduced.

Consequence for the final map: a final-only obligation with no log row is `not_attempted`, so its instance is not terminal and recovery is reported as still warranted. This is honest and is not treated as completed.

## 11. Stop-search (corrected and exact)

Rev 1 mixed two statements. The code is:

- For `state != filled`, `compute_stop_search_certified` returns `True` vacuously. `compute_recovery_needed` never reaches that branch: non-filled requirements take the reason path. The ledger wrapper returns `None` for non-filled.
- For `state == filled`, it returns the clean-completion aggregate. In v3, `c3` is filled and clean, so it is certified and `compute_recovery_needed` returns False in the filled branch. The stop comes from `state == filled`, not from the vacuous branch.

**What I2 changes:** nothing in the function body. Its input `state` changes, because `complete` becomes goal-aware for affected category requirements. A null-only `c3` becomes `partially_filled` and takes the reason path (`category_missing`, recoverable unless budget-spent).

**What I2 does NOT change:** the model-dependence aggregation; the `filled` and clean rule; search terminality, which stays on the completed-search channel (`scoped_search_completed_no_additional_support`) decided per §9. The function is never given a second meaning. A docstring correction stating the vacuous non-filled return may accompany I2-2 (no behaviour change).

## 12. Category cardinality (D13)

`_aggregate_all_requested_categories` counts `complete` instances. After §8 these are goal-satisfied. Derived counts (runtime only, no stored state):

- requested = number of category instances;
- searched/measured coverage = categories with at least one positive or null observation, or a completed obligation for that instance (`scope.instance_key`);
- positive satisfaction (established) = categories with at least one positive observation;
- requested-category completion = established equals requested.

Example: A positive, B null → coverage 2/2, established 1/2, completion not complete. These are never collapsed.
