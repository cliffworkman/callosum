## Architectural decision log

| Decision | Rationale |
|---|---|
| Registration comparison is entered and inspected from Transparency as a responsive paired-evidence workflow, with wrong-match correction blocking new runs (inc 432) | The detected disclosure is the reader's natural entry point. Keeping explicit discovery, confirmation, acquisition, and comparison actions together makes egress/state boundaries legible. Each row shows both evidence columns before explanation/review controls, while raw registration/version and source openings prevent the crosswalk becoming a black box. Incorrect-match rejection persists, visibly stales history, and is revalidated server-side before/background-run to close stale-client races. Neutral/amber/indigo styling and explicit empty-state language prevent aligned rows from reading as a green certificate. |
| Registration comparison is a persisted paired-evidence crosswalk with bounded statuses and derived staleness, never an aggregate verdict (inc 431) | Numeric/threshold/named-field differences can be compared deterministically; other semantic pairs must remain `not-comparable` unless a future gated proposal is human-inspected. Every row copies both available passages/locators, uncertainty, and search scope. Runs fingerprint the registration, article, included supplements, extraction/chunk basis, and pipeline/model versions; changed bases visibly stale prior results while preserving review notes. No run-level compliance, integrity, risk, or deviation score exists, and aligned rows cannot form a positive certificate. |
| Registration-to-publication retrieval is field/section/study bounded before whole-article expansion (inc 430) | Searching entire papers for every plan item raises false matches and makes “not located” uninterpretable. A canonical-field compatibility map therefore selects likely article sections first, local semantic ranking operates only inside that set, nearby context is attached without becoming a candidate, and fallback expansion is recorded. Supplements are opt-in, registration chunks are structurally excluded, and unresolved multi-study identity is explicit ambiguity rather than silent cross-study comparison. |
| Canonical registration commitments are versioned evidence rows, with deterministic structured-provider mapping first (inc 429) | Whole-document comparison would obscure which plan item and evidence produced a flag. Each field is therefore stored independently with verbatim evidence, source question/chunk/page, exact registration hash, and extractor version. OSF schema labels and AsPredicted numbered questions map deterministically; local free text maps only on explicit signals and may remain unmapped. Extraction confidence concerns placement only, never study quality. No LLM/egress is needed for the shipped path. |
| Confirmed registration acquisition stores immutable content-hash versions; structured OSF responses are primary (inc 428) | A later crosswalk must identify exactly which registration version it read. OSF's schema responses retain more faithful commitments than an arbitrary uploaded file, so Callosum deterministically renders ordered question/answer data for local chunks while preserving raw responses, schema/version, amendments, and endpoint snapshots. AsPredicted retains its validated timestamped PDF, and local PDFs share the version seam without invented registry metadata. Re-acquiring identical content reuses it; changed content creates a new attachment/version. Acquisition is explicit, fixed-origin, and separate from confirmation/comparison. |
| Registration discovery is per-run metadata consent + evidence-class candidates, never automatic attachment (inc 427) | OSF exposes direct registration/project relationships but no documented publication-DOI reverse filter; DataCite can return typed related identifiers but a relation such as `References` is evidence, not proof of identity. Therefore discovery sends only DOI/title/detected identifiers after an exact disclosure, uses authors/year locally, preserves provider provenance/errors and relation types, and persists candidate/confirmed/rejected state in `paper_registration_links`. Similarity candidates always require inspection; confirmation records a link and performs no acquisition. OSF/DataCite requests are provider-constructed, bounded, timed out, and never carry document text or credentials. |
| Document role is a required input to paper-level chunk reads; unrestricted reads must be named explicitly (inc 425) | Once registration attachments exist, an ambiguous `paper_id` chunk query can silently contaminate synthesis, search, Methods, summaries, or embeddings. Canonical roles plus exact attachment/role-scoped repository APIs make the safe article-only path structural, preserve legacy primary PDFs by normalization, and reserve an explicitly named all-documents function for rare intentional consumers. |
| Permanent delete removes only exclusively owned, root-contained `managed` attachment files; linked/URL/out-of-root/shared paths survive (inc 340) | Extends inc 65's explicit, trashed-only database/vector purge without crossing Callosum's ownership boundary. `paper_purge.py` normalizes attachment paths, requires `storage_mode=managed` plus containment in the resolved `CALLOSUM_LIBRARY_DIR`, preserves any path referenced by a surviving paper, and stages eligible files via same-volume rename before the existing purge. Normal file/database/vector failures restore staged files and leave the paper in Trash; a staging lock returns 409 and the UI reports it. This is A-A value A4 (the user owns irreversible acts): the easier “unlink every recorded attachment path” design was rejected because it could delete Zotero or other external files. No endpoint/schema/dependency/egress change; audit `2026-07-22_managed-file-permanent-delete.md` PASS. |
