# Security audit — `POST /papers/by-doi` (add a paper by DOI, backlog #58)

**Date:** 2026-09-11
**Scope:** one new API endpoint (`app/backend/api/routers/acquisition.py`) + a shared helper
(`app/backend/metadata/doi_add.py::add_paper_by_doi`, `app/backend/metadata/doi.py::normalize_doi`).
Triggered by the audit gate (#1 new endpoint; #5 net-new feature across ≥3 files).

## What it is

`POST /papers/by-doi {doi, acquire_oa}` resolves a DOI to authoritative metadata (Crossref), dedups
against the library, creates a metadata-only paper, and — opt-in, backend-orchestrated — starts the
existing OA acquisition job on a newly-created paper. It reuses the exact resolve→dedup→create logic the
MCP agent's `save_reference` already used (now both call the shared `add_paper_by_doi`), so this is a new
*surface* on an existing, already-audited capability, not a new fetch capability.

## Threat review

- **Input validation (rule #4):** `AddByDoiRequest.doi` is a pydantic `str` capped at `max_length=255`;
  `acquire_oa` is a bool. `normalize_doi` strips known URL/`doi:` prefixes, lowercases, and **rejects**
  anything that is not `10.<registrant>/<suffix>` (returns None → 422). Only a syntactically-valid DOI
  reaches Crossref. No other field is accepted; no filesystem path is ever built from the input.
- **Data egress (invariant #3):** the only external call is `CrossrefClient.resolve_doi` — the same
  public bibliographic-metadata lookup every other metadata path already makes (polite `mailto`, cached),
  already audited. **No library text leaves**; the DOI itself is the query. This is NOT the Gemini gate
  (no generation), and it makes no genai-host request. The subsequent OA acquisition rides the existing,
  already-audited OA lane (structural `OaLocation`-only, https-only, size-capped) — unchanged here.
- **Honesty / no fabrication:** an unresolvable DOI creates **nothing** (422) — never an invented
  placeholder record. An already-present DOI is surfaced (`status:"existing"`), never duplicated.
- **SSRF:** the endpoint constructs no URL from user input; Crossref is a fixed host, and OA download
  URLs come only from OA databases via `OaLocation` (https + non-IP host enforced), unchanged.
- **Injection:** SQLAlchemy bound parameters throughout (`find_existing_paper_by_identity`,
  `create_paper`); the DOI is a value, never interpolated into SQL or a path.
- **Resource/DoS:** one bounded Crossref lookup + one row insert per call; the OA job is the existing
  bounded async job. No unbounded loop, no large-response risk beyond the already-capped fetchers.
- **Auth/access:** inherits `AccessControlMiddleware` unchanged (local-only by default; bearer-gated when
  Remote access is on). Not added to any gate-exemption list. It is a mutating POST, so a read-only
  companion (`CALLOSUM_READ_ONLY`) rejects it with 403, as intended.
- **Agent path unchanged:** `save_reference` now delegates to the same helper; its behavior (422 on
  invalid/unresolved, `ai-agent` provenance, the `agent_writes` log + Revert) is preserved — regression
  covered by `tests/test_agent_writes.py` (11 pass).

## Negative-path checks (tests/test_doi_add.py, tests/test_agent_writes.py)

- Invalid/garbage DOI (`"not-a-doi"`, `"https://example.com/x"`) → 422, no record created.
- Unresolvable valid-shaped DOI → 422, no record created.
- Existing DOI (any case / `doi:` form) → `status:"existing"`, same `paper_id`, no duplicate, no OA job.
- Created + `acquire_oa:false` → no OA job; created + `acquire_oa:true` → a distinct pollable OA job id.

## Conclusion

A bounded, fail-closed new surface over an already-audited metadata-resolution capability; no new egress,
injection, SSRF, or fabrication surface; the OA bright line is untouched.

**Security Audit: PASS**
