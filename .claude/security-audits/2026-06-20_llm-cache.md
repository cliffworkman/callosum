# Security Audit — Content-addressed LLM generation cache (increment 61)

**Date:** 2026-06-20
**Trigger:** New persistence table (`llm_cache`) + a new caching layer in front of a **trust-critical**
tool (summary generation). Net-new feature spanning 3+ files. (The cache touches the verification spine, so
it is audited even though it adds no endpoint.)

## What changed
- New `llm_cache` table (migration `0005`, additive/idempotent) — content-addressed cache for the
  token-expensive summary generation step. `app/backend/llm/cache.py`: `canonical_hash`, get/set, and the
  `CachedSummaryGenerator` seam wrapper. `conn` threaded into `SummaryGenerator.generate(...)`. New
  `app/backend/llm/usage.py` logs `response.usage_metadata` at the 4 call sites.

## Threat review — the trust guarantees (non-negotiable)
- **Verification still runs on every result (cached or fresh).** The cache wraps ONLY the generation step
  (`CachedSummaryGenerator.generate`); the pipeline's local citation-verification (`pipeline.py:85–94`)
  runs unconditionally on the returned candidates, against the **current** chunks/embeddings. A cache hit
  replays the cached *candidates* and re-verifies them — it can never serve a stale verification verdict.
  Proven by `test_verification_runs_on_cache_hit` (a hallucinated quote stays `flagged` on the cached run).
- **Egress gate behavior is byte-for-byte unchanged.** The cache is layered **inside** the egress gate
  (`EgressGated(Cached(real))`): the egress check runs first (outermost), so egress-off still errors before
  the cache is ever consulted — a cache hit cannot bypass or alter the gate. The inc-58 egress-off tests
  stay green.
- **Key completeness (a stale hit would corrupt a trust tool → correctness-first).** The key is a sha256 of
  EVERYTHING that determines the output: the generator `cache_signature` (model id + `SUMMARY_PROMPT_VERSION`,
  bumped on any prompt/model change) + the chunk SET `[chunk_id, chunk_version, text]` + `scope_ref`. Any
  change → different key → automatic miss (`test_changed_chunk_version_forces_miss`,
  `test_signature_change_forces_miss`). When unsure, the input is in the key (miss-and-recompute is safe).
  No output-determining input lives outside the key → no explicit TTL/event invalidation needed.

## Threat review — the data/store
- **No new data leaves the machine; no new sensitive data stored.** The cache stores the generation output
  (candidate sentences + quotes) keyed by a hash; the chunk text used in the key is already stored in
  `chunks`. Nothing in the cache is sent anywhere — it is read locally to AVOID an external call.
- **SQL / injection:** SQLAlchemy Core bound params only; `namespace`/`input_hash` are app-derived
  (literal `"summary"` + a hex digest), never request data. `OR IGNORE` insert tolerates duplicate keys.
- **Resource:** one row per distinct (model+prompt+inputs) generation; bounded by real usage. The cache
  read/write share the pipeline's transaction (no second connection → no SQLite lock).
- **Input validation / API shape:** no endpoint, no request-schema, no public API change. The
  `generate(..., conn=None)` Protocol addition is internal and backward-compatible.
- **Usage logging:** read-only (`getattr(response, "usage_metadata", None)` → `logger.info`); logs token
  COUNTS only (no prompt/response content), no secrets, no failure surface.

## Negative-path checks (results)
- Cache hit → identical generation output, generator called **once**. **PASS.**
- Changed `chunk_version` / changed `cache_signature` → **miss** (generator re-called). **PASS.**
- Hallucinated quote → `flagged` on the cached run (verification ran). **PASS.**
- Cache persists across app instances (≈restart). **PASS.**
- Egress-off → still errors (cache never consulted); inc-58 suite green. **PASS.**
- Migration 0005 idempotent (fresh DB no-op via 0001 create_all; old DB creates the table); downgrade-to-base
  drops all tables. **PASS.**

Full suite: **223 passed** (+6).

**Security Audit: PASS.**
