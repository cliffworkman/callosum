# Security audit — local custom CSL installation (2026-07-24)

## Scope

Increment 366 adds local `.csl` file installation and explicit update detection to the shared citation-style
manager. Installed personal styles become available to the existing preview, citation, document-render, Settings,
and LibreOffice paths. It adds one API operation (`POST /citations/styles/install`) and a local
`citation-styles/` directory beside `app-settings.json`. It adds a non-mutating validation preflight and one
install mutation operation. It adds no external host, dependency, database schema, background task, credential,
or library-text flow.

## Threat review

- **Request bounds:** filename is capped at 255 characters; CSL text is capped by Pydantic and again by UTF-8 byte
  length at 1,000,000 bytes. XML is capped at 20,000 elements and 100 levels of nesting.
- **XML safety:** DTD and entity declarations are rejected before `ElementTree` parsing. The root must be a CSL
  namespaced `<style>`, version 1.0.x, class `in-text|note`, with a bounded title and an HTTP(S) canonical id.
  Independent styles require a citation layout and must instantiate/render through the real citeproc engine before
  any write. Dependent styles require an exact canonical parent already installed locally.
- **Path safety:** the upload filename is used only to require a `.csl` suffix. Storage ids are generated by the
  server from a normalized canonical-id slug plus a stable canonical hash and must match a strict
  `[a-z0-9-]` grammar. Runtime resolution accepts only fixed bundled ids or generated `custom-*` ids. Custom
  symlinks are ignored. No user path reaches `open`, Node, or a shell command.
- **Immutable bundled assets:** a canonical id matching a bundled style is rejected even with `replace:true`.
  Personal updates overwrite only the file already mapped to the exact same canonical CSL id.
- **Duplicate/update semantics:** identical content returns `already_installed` without a write. Changed content
  under the same canonical id returns `update_available` from the non-mutating validation preflight; only a second
  explicit `replace:true` install writes the update. Expected validation failures also return `valid:false` from
  preflight, avoiding browser-console errors, while direct invalid install calls retain strict 422/409 responses.
  Writes use a temporary file plus atomic `os.replace`.
- **Sidecar boundary:** Python resolves a validated installed id and sends CSL XML in the existing JSON stdin
  request to the fixed Node executable and fixed runner path. The runner applies its own 1,000,000-character cap.
  It never accepts a filesystem path or URL and performs no network operation.
- **Dependent styles:** render-time resolution follows exact canonical ids through installed server-owned files,
  rejects missing/circular dependencies, and caps chains at five levels.
- **Output safety:** citeproc output still passes through the existing text extractor and inline-tag HTML
  sanitizer. Catalog metadata and validation messages render as React text.
- **Egress / SSRF:** local-file text is the only install source. HTTP(S) values inside CSL metadata are identifiers,
  never fetched. URL import and repository installation remain unimplemented.
- **Persistence / secrets:** CSL contains public formatting rules and is stored outside the repository beside local
  settings. No API key, PDF text, library record, or user manuscript content enters validation.

## Negative-path proof

- Wrong extension, empty/oversized input, malformed XML, DTD/entity declarations, excessive depth, missing
  title/id/layout, invalid class/version/id URL, missing dependent parent, and bundled canonical duplicates fail
  before persistence.
- Exact duplicates do not rewrite; changed duplicates require explicit replacement and preserve the server id.
- A valid independent personal style renders both fixed previews and real library records; a dependent style
  renders through its installed canonical parent.
- A manually corrupted or symlinked `custom-*` file is omitted from the catalog and fails rendering cleanly rather
  than expanding path authority or raising an unhandled parser error.
- The installed LibreOffice OXT discovers, previews, inherits, and applies the personal style through the shared
  catalog without receiving a local path.

## Result

**Security Audit: PASS**
