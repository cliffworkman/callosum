# Security audit — Adjustable axis cutoff ("gain") + axis-card redesign (increment 45)

**Date:** 2026-06-19
**Feature:** Make the assigned/uncertain cutoff an adjustable, persisted, per-axis value (default 0.35,
overridable per re-score); redesign the axis card (icon buttons + count badge) + a cutoff flipper.
**Audit trigger:** a request-schema change (`POST /axes/{id}/score` now accepts an optional `gain`) and a
new DB column (`axes.scoring_gain`).

## Surface review
- **`POST /axes/{axis_id}/score`** body `AxisScoreStartRequest { gain: float | None }` — optional; the
  body itself is optional (`payload: AxisScoreStartRequest | None = None`) so the existing no-body call
  still works. `gain` is Pydantic-validated `ge=0.0, le=1.0`, then **clamped to [0.20, 0.60]**
  (`_clamp_cutoff`) before use. A missing/None gain falls back to the axis's saved cutoff, else
  `DEFAULT_AXIS_CUTOFF`. No unvalidated value reaches scoring.
- **`axes.scoring_gain`** — new nullable FLOAT, additive migration `0003_axis_scoring_gain` (idempotent,
  same pattern as 0002; auto-applied on startup). NULL = "use the default". No data loss; existing axes
  simply re-tier at the default on read.
- **`AxisResponse.scoring_gain`** — read-only float (the axis's effective cutoff). No new write surface
  beyond the score endpoint.

## Threat notes
- **Injection / SQL (rule #3):** all SQL is SQLAlchemy Core bound parameters — the persisted
  `update(axes).where(axes.c.id == axis_id).values(scoring_gain=cutoff)` and the read use parameters/ORM
  columns; `cutoff` is a clamped float, never interpolated.
- **Input validation (rule #4):** `gain` validated + clamped server-side; the float can't push the
  scorer out of range (config `__post_init__` also asserts `0 <= uncertainty <= assignment <= 1`, and the
  clamp guarantees ≥ AXIS_FLOOR). Bad/oversized JSON → 422 (Pydantic), never 500.
- **Egress / external calls:** **none.** Scoring + re-tiering are fully local (local embedding model +
  sqlite-vec); the gain change adds no network path.
- **Resource caps:** a re-score is the existing bounded async job (one per request); the gain only shifts
  a threshold, not the work. No new unbounded loops.
- **File-path / ingestion / secrets / auth:** unchanged — none touched. No new dependency.
- **Frontend:** the cutoff flipper is a clamped range input; the value is sent as the validated `gain`.
  Icon buttons reuse existing handlers (edit/add/delete) with `stopPropagation`; no new data exposure.
- **Route surface:** route paths/methods unchanged → `test_health` route-surface invariant still holds
  (the score route already existed; only its optional body grew).

## Negative-path checks (run)
- Full `pytest` green (**149**), incl. `test_axis_cutoff_is_adjustable_and_persists` (default 0.35;
  explicit gain re-tiers + persists; round-trips via GET /axes) and `test_axis_score_is_never_empty`
  (absolute-path never-empty). `test_largest_gap_*` confirms never-empty did NOT leak into other modes.
- Migration auto-applies on startup (`test_startup_migration` updated; live E2E migrated a fresh DB to
  0003). Live browser E2E: cutoff set + re-score persists + survives reload; **0 console errors**.

## Verdict
**Security Audit: PASS** — local-only, validated + clamped numeric input on an existing route, an
additive nullable column with an idempotent migration, no new egress/ingestion/auth/dependency surface.
