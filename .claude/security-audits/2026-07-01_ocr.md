# Security Audit — Local OCR for scanned PDFs (inc 231, backlog B3)

**Date:** 2026-07-01
**Feature:** `POST /papers/ocr/run` — render a scanned PDF's pages, run the local **Tesseract** binary to produce a
*searchable PDF* (image + embedded OCR text layer), attach it as the primary, and extract it through the normal
chunk + embedding pipeline. Files: `app/backend/pdf_processing/ocr.py`, `app/backend/api/routers/ocr.py`,
`app/backend/api/app.py` (wiring), `app/frontend/js/25_detail.jsx` (button).

**Audit-gate triggers:** a new API endpoint (#1), a new subprocess + file-write path (#3), a net-new feature across
3+ files (#5). **NOT triggered:** a new external fetch/integration (#2 — no network) and a new third-party
dependency (#6 — Tesseract is a *system binary*, not a pip package; the cloudflared/Node precedent).

## Threat review

- **Command injection / subprocess safety.** The Tesseract invocation is a **fixed argument vector**
  `["tesseract", "stdin", "stdout", "-l", lang, "pdf"]` (`ocr.py::_default_page_runner`). The page **image is piped
  via stdin** and the searchable PDF read from **stdout** — **no filename or client-supplied string ever reaches the
  command line**. `lang` is a module constant (`"eng"`), not request-derived. `shutil.which("tesseract")` resolves
  the binary (no shell, `shell=False`). A per-page **timeout** (`TESSERACT_TIMEOUT_S = 180`) bounds a hung process.
- **File-path safety (read).** The source PDF path is resolved **only** from the trusted attachment row via
  `_select_primary_pdf_attachment` + `_local_attachment_path` (`paper_files.py`, the inc-91 audited resolver) — never
  from client input. The endpoint takes only an integer `paper_id`.
- **File-path safety (write).** The searchable copy is written **only** under `library_dir()` (env
  `CALLOSUM_LIBRARY_DIR` or the project `library/`), with a name derived from the paper's own metadata via
  `library_filename_for` + `_sanitize_filename` + an `(OCR)` suffix, and **deduped** by `_unique_ocr_path`. No client
  string is used in the path; no traversal surface. `out.save(..., garbage=3, deflate=True)` compresses the copy.
- **Resource caps (rule #4).** `MAX_OCR_PAGES = 200` bounds pages OCR'd per run; the per-page subprocess timeout
  bounds each page; render DPI is a fixed 300. The job is async (a slow OCR never blocks the request loop) and
  ephemeral (in-memory `JobStore`, cleared on restart).
- **Fail-closed / graceful degradation.** A missing binary raises the typed `TesseractUnavailable` (mirrors
  `CitationEngineUnavailable`); the worker catches it → the job status is `error` with a clear *install Tesseract*
  hint. Any render/engine failure is caught → `mark_error(f"{type}: {exc}")` — **never a crash**. Proven by
  `test_ocr_job_fails_gracefully_when_tesseract_missing`.
- **Egress.** **None.** Tesseract runs locally; chunk embedding uses the local model + local vector store. No network
  call of any kind — this is **not** the Gemini library-text gate. Stated in the router docstring.
- **Input validation at the boundary.** The endpoint validates synchronously: **404** unknown paper, **422** no local
  PDF, **422** the paper already has a text layer (`get_chunks_for_paper`) — so OCR only ever runs on a scanned,
  chunk-less PDF and only *adds* chunks (no destructive delete/re-chunk path exists).
- **Data integrity / non-destructive.** The original scanned attachment is **kept** (demoted to `role="secondary"`);
  the OCR'd searchable copy is added as the new `role="primary"`. Nothing is deleted. Proven by
  `test_ocr_endpoint_makes_a_scanned_paper_searchable` (2 attachments remain; the primary is the OCR copy).
- **Coordinate honesty (invariant #2).** The searchable copy has a **real, correctly-positioned text layer**, so
  exact highlights come from the **unchanged** quote-location pipeline reading that layer — no fabricated
  coordinates, no changes to the honesty-critical code. Pages are rebuilt from upright rasters, so the copy has no
  page rotation (the overlay's rotated-page skip never applies). The OCR provenance is recorded on the attachment
  (`import_source="ocr"`) so a future UI can caveat "OCR'd text."
- **Supply chain.** No new pip dependency (PyMuPDF + numpy already pinned; Tesseract is an external system binary the
  user installs, like Node). No package to pin/vet.

## Negative-path checks (all in `tests/test_ocr.py`, hermetic — a fake page-runner, no binary)

- Tesseract absent → job `error` with the install hint (no crash). ✔
- Unknown paper → 404; paper with no local PDF → 422; paper that already has text → 422; unknown job id → 404. ✔
- The searchable copy is genuinely searchable (the normal extractor finds the OCR'd text) + the original attachment
  is preserved. ✔

**Security Audit: PASS.** Local-only (no egress), fixed-argv subprocess with the image piped via stdin (no injection),
trusted DB-derived read + a sanitized/deduped write under `library_dir()`, bounded + timed + fail-closed, additive
(no delete), no new dependency. Re-audit only if OCR later gains a batch endpoint over client-supplied paths or a
cloud OCR backend (egress).

## inc 231 addendum — binary resolution (installed-but-not-on-PATH)

`_default_page_runner` now resolves the binary via `tesseract_exe()`: `CALLOSUM_TESSERACT_PATH` (env override) →
`shutil.which("tesseract")` (PATH) → a **fixed** list of common install locations (`C:\Program
Files\Tesseract-OCR\tesseract.exe`, Homebrew/apt paths). This is because the UB-Mannheim Windows installer doesn't add
Tesseract to PATH, so `shutil.which` missed an installed binary. **No new attack surface:** the candidate paths are a
hardcoded constant (not request-derived); the env override is the operator's own local machine config (same trust as
`CALLOSUM_DB_URL`/`CALLOSUM_LIBRARY_DIR`); each candidate is `Path.is_file()`-checked before use; the subprocess still
uses a fixed argv with the image piped via stdin. **Real-binary round-trip verified** (Tesseract v5.4.0): an image-only
page → `tesseract stdin stdout pdf` → a searchable PDF the normal extractor reads the recovered text from. Still PASS.
