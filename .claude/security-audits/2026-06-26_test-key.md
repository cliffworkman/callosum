# Security audit — "Test this key" egress-gated ping (inc 147)

**Date:** 2026-06-26
**Trigger (audit gate):** a new API endpoint (`POST /settings/test-key`) + an external fetch (a minimal Gemini call).

## What it does

A **Test key** button in Settings → AI features makes a tiny, **non-library** call to Gemini with the resolved key
to confirm it authenticates + can generate, and reports ✓/✗. It exists so a BYOK user can validate a pasted key
without running a full summary.

## Threat review

- **Egress invariant (#3) — strengthened, not weakened.** The endpoint refuses to contact Google unless
  `GeminiConfig.from_environment().data_egress_enabled` is true: with "Allow AI features" OFF it returns
  `{ok: false, detail: "Turn on Allow AI features first…"}` and **constructs no genai client / makes no network
  call** (tested). So the egress toggle's promise holds: OFF ⟹ zero outbound AI calls. No new egress path is
  introduced (it rides the existing library-egress consent — the chosen, conservative reading over a lighter
  "test-before-consent" model).
- **Payload.** The call sends a **fixed non-library string** ("Reply with the single word OK."), never library
  text, chunks, metadata, or the user's data. (Even so, it's gated on egress per above.)
- **Secret handling.** The key is read via `resolved_api_key()` and passed only to `genai.Client(api_key=...)`.
  It is **never logged** and **never returned** — any error message is **redacted** (`str(exc).replace(key, "***")`)
  and length-capped before being put in `detail`, so a provider error can't echo the key back. The response is
  only `{ok, detail}`.
- **Input validation.** No request body (a parameterless POST action). No user input reaches SQL/shell/path.
- **Failure handling.** All provider/network exceptions are caught → `{ok: false, detail: <redacted>}` (never a
  500); a missing key → `{ok: false, detail: "No API key is set."}`.
- **Resource / abuse.** One bounded generate per click (tiny prompt); no loop, no fan-out.
- **Supply chain.** No new dependency (reuses `google-genai`, already a dep).

## Negative-path checks

- Egress OFF → `ok:false`, the genai pinger is **not** called (spy asserts 0 calls). ✅ (test)
- Egress ON + no key → `ok:false` "No API key is set." ✅ (test)
- Egress ON + key + pinger stub → endpoint returns the pinger's result. ✅ (test)
- A provider error containing the key → the key is redacted from `detail`. ✅ (unit test of `_ping_gemini` redaction)

## Result

**Security Audit: PASS.**
