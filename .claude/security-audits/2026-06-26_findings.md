# Security Audit — Findings subsystem (the FACT-vs-CANDIDATE contract), inc 130

**Date:** 2026-06-26
**Feature:** A persistent per-paper findings store + review surface. Findings are typed rows
(`kind` = fact | candidate) keyed by a deterministic `content_key`, written by producers via
`upsert_findings`, read per-paper + as a library overview, and reviewed (candidate → confirmed /
accepted / noted). v1 ships the **contract + UI only** — no producer wired yet (retraction is next).

**Audit-gate triggers:** #1 (new API endpoints — 3), #5 (net-new feature spanning 3+ files /
~300+ LOC). Not #2 (no external fetch), not #3 (no file ingest/write), not #6 (no new dependency).

## Surface

- Schema: new `paper_findings` table (migration **0016**, additive/guarded), FK `paper_id` → `papers`
  CASCADE, unique `(paper_id, source, content_key)`, index on `paper_id`.
- Data access: `app/backend/persistence/findings_repo.py` (`upsert_findings`, `get_paper_findings`,
  `findings_overview`, `set_review_state`, `get_finding_dict`).
- Endpoints (`app/backend/api/routers/findings.py`):
  - `GET /papers/{paper_id}/findings` — read-only; 404 if the paper is missing.
  - `GET /findings/overview` — read-only; one row per paper with ≥1 finding.
  - `POST /findings/{finding_id}/review {state, reason?}` — the only mutation; 404/422 on bad input.
- Frontend: `08_methods_findings.jsx` (the METHODS "Review" section) + a read-only library badge.

## Threat review

- **Input validation.** `paper_id` / `finding_id` are path ints (FastAPI coerces; non-int → 422).
  `ReviewRequest.state` is free text but `set_review_state` allowlists it (`confirmed`/`accepted`/`noted`
  → else `"bad-state"` → **422**); `accepted` requires a non-empty trimmed `reason` (else `"needs-reason"`
  → **422**); a non-candidate or unknown id → `"not-candidate"` / `"not-found"` → **404**. No state reaches
  SQL unvalidated.
- **SQL injection.** SQLAlchemy Core throughout, bound parameters only (rule #3). No string interpolation;
  table/column names are constants. `content_key` is `sha256` hex (producer-supplied payloads are JSON, not
  SQL). PASS.
- **Output encoding.** Finding payload text + `review_reason` render via React text nodes (auto-escaped) —
  no `dangerouslySetInnerHTML`. A malicious producer string can't inject script into the UI. The payload is
  JSON-validated on the column (SQLAlchemy JSON type).
- **Egress.** Entirely local — no network call, no LLM, no Gemini. The egress gate is not on this path and
  correctly not invoked. A negative-path check confirms **0 genai-host requests** in the headed run (egress
  unset). PASS.
- **Resource caps.** Reads are bounded by the library size (overview groups by paper). `upsert_findings`
  is producer-facing (not a public endpoint in v1) — a producer is trusted server-side code; when the first
  producer (retraction) lands it caps its own fetch. No user-supplied unbounded loop on the public surface.
- **File-path safety.** No filesystem access introduced.
- **Authorization.** Local single-user model unchanged; no new auth surface. (The standing "before hosted
  deploy" note already covers adding auth/rate-limiting globally.)
- **Supply chain.** No new dependency.

## Principle / value posture (cross-check, not a substitute for the rule-#9 gate)

- **FACT vs CANDIDATE (#3).** The schema encodes the distinction structurally (`kind`); facts carry
  `review_state = NULL` (not reviewable), candidates `unreviewed` until the human acts. The UI renders facts
  as neutral marks, candidates as reviewable cards.
- **Signal not verdict / no composite score (#2/#7).** The library badge counts the user's **unreviewed
  work** ("N to review"); it is never a quality/score/rank and shows nothing at zero. No aggregate verdict.
- **No accusation (A-A veto).** A finding is a list item the human confirms/accepts/notes; nothing
  auto-acts, nothing labels a paper or author. Held.
- **Inspectability / human-is-the-filter (#5/#8).** Every candidate routes to its page (region precision —
  no fabricated exact highlight, coordinate-honesty intact); `accepted` records the human's reason.

## Negative-path checks (run)

- `POST /findings/{id}/review` with `state="bogus"` → **422** (`test_findings.py`).
- `accepted` with empty reason → **422**; with reason → **200** (`test_findings.py`).
- review on a non-existent finding id → **404**; on a fact (non-candidate) → **404**.
- `GET /papers/{missing}/findings` → **404**.
- Headed run (egress unset): **0** requests to any genai/Gemini host; **0** console/page errors.

## Result

**Security Audit: PASS.** Local-only, bound-param SQL, validated/allowlisted review input, escaped output,
no egress, no new dependency. The producer-facing `upsert_findings` is trusted server-side; the first real
producer (retraction) will be audited for its own external fetch when it lands.
