# Security + Principles review — the literature Feed (SP2a), inc 187

**Date:** 2026-06-28
**Feature:** the Feed engine + store + endpoints + the bioRxiv-by-category source. New `schema_feed.py`
(`feed_subscriptions` + `feed_items`, migration **0021**), `persistence/feed_repo.py`, `discovery/feed.py`
(`FeedSource` registry + `refresh_subscriptions` + `feed_view`), `discovery/biorxiv_source.py`, `routers/feed.py`
(8 endpoints), wired in `app.py`. Backlog #28 SP2a (the Feed tab UI is SP2b).

**Audit gate triggers:** new API endpoints (8); a new external fetch (bioRxiv API); a new write path (storing polled
items); a migration; a net-new feature spanning 3+ files.

## Principles / values gate (rule #9 + A-A)

A discovery surface, **not** a claim/judgment about the literature → the charter triggers lightly; the relevant layer
is the **values** posture on "feeds/notifications" (A-A consent value), settled in the design spec and honored:
- **Pull-only, opt-in, source-level.** A source is followed only by an explicit `POST /feed/subscriptions`; there is
  **no auto-subscribe** and **no push/notification** — `POST /feed/refresh` is the only poll, user-initiated. (The UI
  in SP2b stays pull-first; any future cadence/notification is opt-in + source-level.)
- **Augment never filter.** The Feed shows the complete polled list (read/starred are user state, not an AI verdict);
  nothing is hidden or ranked by a model.
- **User-derived.** Subscriptions come from the user's explicit choice (and, later, suggestions from their own
  library) — never auto-added. The declined misaligned path: an opinionated push feed that decides what's important.
**Aligned.**

## Security threat review

### SSRF / external calls
- The only outbound fetch is bioRxiv: `GET https://api.biorxiv.org/details/biorxiv/<from>/<to>/<cursor>/json` — a
  **constant host**; the path segments are **server-derived dates** (`datetime.date.today()` ± a window) and an
  integer cursor, **never user input**. The subscribed **category is filtered client-side** (it never enters the URL),
  so a malicious category value cannot redirect or inject the fetch. httpx timeout (20s); non-200 / empty page → stop
  (fail-closed); bounded by `max_pages` (6) × page.
- A source that raises is swallowed by `refresh_subscriptions` (one bad source/subscription never aborts the run).

### Input validation (rule #4)
- `SubscriptionRequest` bounds `kind` ≤40 / `value` ≤500 / `label` ≤300; **`kind` must be a registered source kind**
  (else 422 — no arbitrary source). `GET /feed` bounds `limit` 1..500. `record_to_entry`/`summary` parsing is
  defensive (tolerates missing fields; drops no-title-and-no-DOI; authors split safely; year from a 4-digit prefix).

### Injection (rule #3)
- All persistence is SQLAlchemy Core bound parameters (`feed_repo`): subscription get-or-create, item INSERT-OR-IGNORE
  on (subscription_id, dedup_key), state updates, the unread count. No request/bioRxiv data reaches SQL text. `kind`
  is validated against the registry; `value`/metadata are bound values.
- **Re-poll is non-destructive:** INSERT-OR-IGNORE never duplicates a row or resets the user's read/starred state.

### Data egress (invariant #3)
- Polling sends **no library data** — only the server-derived date window to bioRxiv (public metadata). No
  Gemini/genai host is contacted (the QA route asserts 0 genai requests). `feed_view` computes `in_library` locally.
  Save reuses `/discovery/save` (metadata-only, **no PDF** — the OA-acquire lane is untouched, no paywall
  circumvention).

### Secret handling / supply-chain / resource caps / file-path safety
- No secret introduced (bioRxiv is keyless). No new dependency (httpx). `max_pages`/`limit_per`/`limit` cap work +
  result size; the async refresh runs in a worker connection (`app.state.engine.begin()`), like the gap-finder. No
  filesystem path is built from request/external data (no file write — items are DB rows).

### Migration
- 0021 is **additive + idempotent + guarded** (create-if-absent), matching 0002–0020; no down-migration (project
  convention). Tests derive the head via `alembic_head()` (no hardcoded revision).

## Negative-path checks
- Unknown `kind` → 422; duplicate subscription → get-or-create (no second row); re-poll → 0 new + read state preserved;
  a raising source → run completes (`test_refresh_skips_a_failing_source`); delete cascades; `in_library` read-time
  truth (`test_refresh_upserts_and_view_marks_in_library`); bioRxiv mapping + category filter + dedup
  (`test_biorxiv_*`). Live spot-check (neuroscience, 10-day window) → 5 real entries mapped end-to-end.

## Decision

**Security Audit: PASS.** Constant-host, server-derived-path, category-filtered-client-side fetch (no SSRF);
bound-param persistence; non-destructive re-poll; bounded; public-metadata egress (not the Gemini gate); additive
guarded migration; no new dependency. **Values: aligned** — pull-only, opt-in, no auto-subscribe, augment-never-filter.

## Addendum (SP2c, inc 189) — the PubMed-keyword Feed source + the data-driven Follow picker

**Added:** `PubMedKeywordFeedSource` (`kind="pubmed_query"`) in `pubmed_provider.py` — a saved PubMed query as a Feed
source — registered into the default `FeedRegistry`; `FeedSource` display metadata (`label`/`placeholder`/`suggestions`)
exposed via `GET /feed/subscriptions` as `source_meta`; the Follow UI is now a **data-driven** source picker.

- **External fetch (NCBI E-utilities):** reuses the **already-audited** `_eutils_search` (inc 186 PubMed Search) — the
  **constant** `eutils.ncbi.nlm.nih.gov` host with the query as a bound `term` param (no SSRF), esummary `id` built only
  from digit-validated PMIDs, fail-closed, `retmax ≤ 50`. The only new wrinkle is `sort="date"` (a bound param, not a
  host/path), so the feed polls newest-first; mapping (`record_to_feed_entry`) is defensive (drops no-title-and-no-DOI;
  posted_date from `sortpubdate`). Public-metadata egress — **not** the Gemini gate. Live spot-check (`crispr
  off-target`, 3) → 3 recent records mapped.
- **No new endpoint/migration/dependency:** the source drops into the existing `/feed/*` (the inc-187 audit covers the
  store + endpoints). `source_meta` is **display metadata only** (kind/label/placeholder/suggestions — non-secret, no
  request data, defensive `getattr` defaults); the `kind` allowlist validation (422 on unknown) is unchanged. The
  Follow picker renders from `source_meta`, so a future source needs no frontend edit (the registry promise).
- **Values:** unchanged — still pull-only, opt-in, augment-never-filter; a PubMed *query* you choose to follow.

**Addendum decision: PASS** (a second feed source on an already-audited host + non-secret display metadata).

## Addendum 2 (SP2c-2, inc 190) — the journal-by-ISSN Feed source

**Added:** `JournalIssnFeedSource` (`kind="journal_issn"`, `journal_issn_source.py`) — follow a journal by its ISSN →
its recent articles via Crossref `/works?filter=issn:…&sort=published&order=desc` — registered into the default
`FeedRegistry`. **No frontend/endpoint/surface change** (the data-driven Follow picker rendered the new option from
`source_meta`; the QA surface map is unchanged at 132 API / 655 FE).

- **External fetch (Crossref):** reuses the **already-audited** Crossref host (constant `api.crossref.org/works`,
  inc 183 Search). The ISSN is **validated against `^\d{4}-\d{3}[\dX]$` before any request** (invalid → no fetch), then
  passed only as a bound `filter=issn:<issn>` param — it never reaches the host/path → **no SSRF**. `sort`/`order`/`rows`
  are constants; `rows ≤ 50`; fail-closed on non-200/non-JSON. Mapping reuses the audited `message_to_item` (drops
  no-title-and-no-DOI) + `_published_date` (date-parts → `YYYY-MM-DD`). Public-metadata egress — **not** the Gemini
  gate. Live spot-check (Nature, `1476-4687`, 3) → 3 recent articles mapped.
- **No new dependency/endpoint/migration/secret** (httpx; the mailto is the same polite-pool contact).
- **Values:** unchanged — pull-only, opt-in, augment-never-filter; a journal you choose to follow.

**Addendum 2 decision: PASS** (a third feed source on an already-audited host; ISSN validated + bound filter; no new
surface — the registry promise held end-to-end, backend through UI).
