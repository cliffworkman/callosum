Goal: cut LLM token spend without degrading functionality or the citation-verification guarantees. A cache
hit costs **zero tokens** — the dominant lever. This pass implements the clearly-safe, functionally-neutral
wins (a persistent content-addressed cache on the top-offender summary path + usage instrumentation) and
**proposes the rest with a measurement/verification plan, stopping for review**.

## Deliverable 2 — implemented vs deferred
### Implemented (clearly-safe, functionally-neutral)
- **Content-addressed SQLite cache on the summary path.** Key = `sha256(canonical_json({sig, chunks:
  [[id, chunk_version, text], …], scope}))` where `sig` = `cache_signature` (model + `SUMMARY_PROMPT_VERSION`).
  Any input change → different key → automatic miss (no explicit invalidation). **Negative results are
  cached for free** (an empty candidate list is a valid cached value). Persisted in `llm_cache` (migration
  `0005`) → savings survive restarts.
- **Usage logging** at all 4 call sites (`response.usage_metadata` → `logger.info`), read-only — gives real
  token numbers to size the deferred levers.

### Deferred for review (proposed with a plan)
- **Extend the cache** to help (corpus-hash key), cluster labeler (per-cluster; fixes the eager re-spend),
  term suggester (label+desc) — one-liners on the generic module, each with its own prompt-version constant;
  gate on the usage log clearing the bar.
- **Output caps** (`max_output_tokens` sized from the log) + `response_mime_type="application/json"` — verify
  the parsers, measure first (output is the priciest token, ~4×).
- **top_k right-sizing** — trades recall; measurement plan via `tools/validation_harness.py` (verified-citation
  counts at top_k 8/6/4).
- **Gemini provider-side / implicit prefix caching** for the repeated summary instruction + help corpus
  prefixes — verify current behavior + pricing against Gemini docs first.
- **Gemini Batch API** (~½ price, 24h) for the non-interactive validation harness — latency-tolerant, dev-tool.
- **Request coalescing** — near-zero value for a single-user app (the cache covers sequential repeats).

## Key technical detail (correctness layering)
The cache sits **inside** the egress gate (`EgressGated(Cached(real))`) so egress-off behaves exactly as
before (errors before the cache is consulted — a hit can't bypass the sacred gate), and it uses the
pipeline's **existing `conn`** (threaded into `generate()`); a second SQLite connection mid-transaction
would lock, and the cache row commits atomically with the summary. **Verification (`pipeline.py:85–94`)
runs on every result, cached or fresh** — a hit replays the cached *candidates* and re-verifies them against
the current chunks/embeddings, so a hit can never serve stale verification. `SUMMARY_PROMPT_VERSION` is part
of the key, so editing the prompt (or the model) can never serve outputs generated by the old prompt.
