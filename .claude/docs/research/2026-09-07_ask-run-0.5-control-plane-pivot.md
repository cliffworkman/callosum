# Ask control-plane pivot — Run 0.5 design addendum

**Status:** architectural codification + a narrow component-calibration plan (Run 0.5). No production
code changes. Companion to, and refinement of, the scoping report
`2026-09-07_ask-cli-experiment-scoping.md` (which this cross-references). Frozen benchmark question and
verifier thresholds are unchanged; the model stays Qwen2.5-1.5B-Instruct Q4_K_M.

This document records a pivot in **how Callosum uses a small local language model inside the staged Ask
pipeline**. It is the durable statement of intent; the Run 0.5 calibration harness
(`experiments/ask_cli_revised/calibration/`) is its first empirical test, scoped to the two upstream
*control* tasks only (question decomposition and context selection), replayed against artifacts the
completed baseline already produced.

---

## 1. Motivation — what the baseline localized

The revised baseline (`runs/revised-20260907T211542Z/`) ran end-to-end but sealed **one** verified
proposition. The postmortem localized the dominant loss to the **upstream Qwen control tasks**, and
found two *distinct* failure classes that a single fix would not both address:

- **Format compliance.** The 1.5B does not reliably emit bare control JSON. Handed a passage, it
  continues or paraphrases the passage, then hits a tiny no-grammar output cap (48 / 96 tokens) before
  any JSON appears. Result: **99 of 140 calls truncated → deterministic fallback → a starved ledger.**
  The intermediate tasks were deliberately run with `contract=None` (no llama.cpp grammar), even though
  primary-synthesis and axis-labeling already solve this identical "won't emit bare JSON" problem *with*
  a grammar.
- **Semantic control.** Format is not the whole story. One fully valid, parseable context-gate call —
  handed the anomalous-is-bad study's own abstract, which *explicitly* names the amygdala, economic-game
  behavior, and attitudes — returned `{"action":"discard"}`. Merely forcing valid JSON would not have
  saved that evidence.

Two named specimens carry through Run 0.5:
- **the `discard` specimen** — the anomalous-is-bad abstract packet the gate discarded despite direct,
  on-topic findings being present in the supplied text; and
- **the "psychological theories" hallucination** — Stage-1 decomposition inventing a subquestion
  (`s4: "what psychological theories explain these phenomena?"`) the user never asked, while
  simultaneously dropping explicit requests (scales, cross-cultural evidence, cultures, measurement,
  interventions).

The pivot below responds to both classes at once.

---

## 2. The old counterfactual context controller, and why it fails

The baseline context gate asked one question with five answers —
`accept / before / after / both / discard` — and thereby conflated judgments that are not the same
judgment:

- *Is this text intelligible on its own?*
- *Does it need more context, and in which direction?*
- *Is it relevant to the question?*
- *Is it evidence?*
- *Should this branch survive at all?*

Worse, `before / after / both` require the model to **reason about text it has not been shown** — to
predict what the neighboring chunks probably contain. A small model asked to predict unseen text falls
back on its prior and completes plausibly rather than faithfully. And `discard` gave a cheap upstream
language call the authority to **delete evidence permanently** — an epistemic execution performed before
the conservative verifier ever ran.

---

## 3. The evidence-conditioned replacement (Core Principle 2)

**Prefer evidence-conditioned judgments over predictions about unseen evidence.** If Callosum can show
the model the relevant source material before asking for a judgment, it must. Avoid questions of the form
"would more context help?", "what probably precedes this?", "what might be missing?", "should we keep
reading?" — each asks a generative model to reason about text it has not seen, and each invites
model-prior completion.

Ask instead: "*which of these supplied windows is sufficient?*", "*does this supplied exact span state a
finding?*", "*does this supplied claim answer this supplied request?*" The model **looks at what is
there before deciding.** This is an epistemic design principle, not a prompt tweak.

---

## 4. Minimum-sufficient-context formulation (Core Principle 4)

Replace the counterfactual gate with a selection over **real, increasingly broad context envelopes**
built deterministically around a clearly marked central retrieval chunk:

- **A** = central chunk only
- **B** = ±1 neighbor (≤3 chunks)
- **C** = ±2 (≤5 chunks)
- **D** = ±3 (≤7 chunks)
- **E** = even the largest supplied local envelope does not make the central chunk intelligible as part
  of a complete scientific idea

Qwen chooses the **smallest supplied envelope in which the central chunk's scientific idea becomes a
complete, interpretable thought**. At document boundaries it uses whatever real neighbors exist (stated
explicitly, never faked into symmetry, never synthesized). The central chunk is marked in every envelope.

Two things this primitive deliberately does **not** ask at this stage: whether the packet answers the
user's question, and whether the central material should become evidence. Those are later, separate
stages. Critically: **E means "bounded local context is insufficient," not "delete this branch."** There
is **no destructive DISCARD operation** in the context-control primitive at all.

---

## 5. Context is for interpretation; evidence is for support (Core Principle 3)

Keep two concepts distinct:

- **context envelope** = what Callosum read to *understand* the source idea, and
- **evidence anchor** = the specific source span whose verbatim substring is cited to *support* a
  proposition.

A larger envelope may be read to understand an idea without making every chunk in it evidence. Exact
evidence remains anchored later to the one span that supports the claim (possibly a neighbor of the
retrieval anchor). Surrounding chunks stay interpretive context and are never concatenated into "one
quote."

---

## 6. Asymmetric error costs (Core Principle 5)

The target is **minimum *sufficient* context, not merely minimum context.** The two errors are not
symmetric:

- true minimum = C, model picks A → the idea may be **misunderstood** (serious);
- true minimum = B, model picks C → **mild inefficiency**.

So **under-expansion is penalized more heavily than over-expansion.** Primary objective: enough real
source context to interpret the central material correctly. Secondary objective: avoid unnecessary
context. Scoring treats A < B < C < D < E as an ordinal scale and reports sufficiency-retention as the
primary metric, minimality/token-efficiency as secondary.

---

## 7. Implications for tiny-model task design (Core Principles 1 & 6)

**Qwen speaks language; code speaks schemas** (Core Principle 1). The small local model provides
natural-language interpretation. Deterministic code owns IDs, schemas, bookkeeping, provenance, exact
source strings, iteration bounds, branch survival, evidence ancestry, coverage accounting, and verifier
policy. Do not hand the model administrative work merely because structured JSON makes implementation
convenient. When a task proves unreliable, the response is to **decompose it further or condition it on
visible evidence**, never to broaden the prompt or grant more epistemic freedom.

**Discovery may be curious because verification stays conservative** (Core Principle 6). An inexpensive
upstream language judgment must never become an epistemic executioner. A false positive upstream costs
computation; a false negative upstream can permanently remove valid evidence. If irrelevant material
survives into evidence screening, later stages reject it; if an unsupported claim reaches the verifier,
the verifier rejects it. The asymmetry favors letting material through.

### 7a. Decomposition self-audit as "look at what is there before deciding"

The same evidence-conditioned principle applies *before retrieval*, to the decomposition itself. A
decomposition is a claim about the user's request; it should be **evaluated against the original request
before it is allowed to drive retrieval**, and a failed evaluation should produce **evidence-conditioned
targeted repair, not blind regeneration.**

The audit is deterministic and local (cosine over the already-loaded embedding model on a handful of
short strings — not corpus re-embedding):

1. **Global reconstruction** — cosine(original question, aggregate text of the retained items): does the
   decomposition *as a whole* still represent the user's question? A quality gate on the whole, **never**
   a per-item delete rule.
2. **Per-source-unit coverage** — for each deterministic source unit, its best match among the items:
   is every explicit part of the request represented somewhere? This protects a small-but-important
   request (scales, cross-cultural evidence, interventions) from being masked by a high global score.
3. **Leave-one-out contribution** — `delta_i = full − without-i`, read only diagnostically: large
   positive = materially contributes; ~0 = redundant/peripheral; negative = the aggregate improves
   without it, so the item is *suspicious*.
4. **Optional pairwise redundancy** — if cheap, flag items expressing the same request.

When the global gate fails **or** a source unit is poorly represented, perform **targeted repair**: show
Qwen the original question, the relevant source unit(s), the current decomposition, which units are
poorly represented, and which items have weak/negative leave-one-out contribution, and ask it to revise
**only** the questionable item(s) — preserving the rest. Do not ask it to explain why the metrics
failed; do not feed it scientific answer content. It repairs *language* using visible evidence about the
decomposition. The loop is **bounded**: initial → audit → at most one targeted repair → re-audit; a
still-inadequate result falls back conservatively to the deterministic source units.

**The non-destructive rule is load-bearing: semantic similarity is measurement, anomaly-detection, and
repair-guidance — never epistemic authority.** No `low-similarity → delete` or `negative-LOO → delete`
path exists. Canonical source units remain protected by deterministic provenance. A plausible
hallucinated item can itself be highly similar to the question, so similarity can never establish
provenance or correctness; only deterministic source-unit derivation can.

## 8. The Run 0.5 calibration plan

Run 0.5 is a **replay-and-calibration harness**, not an Ask run. It reuses the baseline's frozen DB copy
and stage artifacts so no embeddings/discovery/retrieval/NLI/verification/coverage/recovery/terminal
work reruns while the two control tasks are tuned. Only two components are in scope:

- **Decomposition / request preservation** — compares three designs over the frozen AIB question (plus a
  small set of existing complex questions if cheaply found): **A** single rewrite per source unit; **B**
  multi-rewrite per bundled unit; **C** source-preserving + the §7a self-audit + one bounded targeted
  repair pass. Success = zero silent request loss, zero unsourced additions, source provenance on every
  rewrite, near-zero structured-output failure, reasonable latency; preserving exact source text is an
  acceptable fallback.
- **Minimum-sufficient-context** — supplies real A/B/C/D envelopes around baseline retrieval anchors and
  scores Qwen's smallest-sufficient choice against careful human reference labels (with acceptable-set
  ambiguity), under the asymmetric metric. The `discard` specimen is a mandatory regression case (dev).

Both tasks use a llama.cpp/ollama structured-output grammar (the mechanism primary-synthesis already
uses); structured-output enforcement is verified by neutral smoke tests **before** calibration, and if
it cannot be enforced through the Juno/ollama topology the run **stops and reports** rather than silently
reverting to unconstrained JSON. Datasets and the held-out split are frozen before any prompt tuning;
each chosen design is evaluated once on held-out; then Run 0.5 stops and hands back.

### What remains unresolved (for a later, separately-approved pass)

- Whether fixed **chunk-count** envelopes (±1/±2/±3) are the right unit, or whether **token/character-
  bounded** envelopes behave better under Callosum's real chunking — a primary thing Run 0.5's human
  window-review artifact is meant to inform.
- Whether decomposition should ultimately emit **one vs several rewrites** per source unit (Design A vs
  B vs C is the first evidence).
- The empirical **audit-gate threshold** for Design C (a Run 0.5 calibration parameter, not yet a
  production constant).
- **Transfer** from the ollama replay runtime to the shipping llama.cpp `b10516` runtime (same weights,
  different engine) — Run 0.5 measures on ollama; a shipping-runtime check is a later step.
- The downstream tasks (evidence selection, proposition formation, obligation mapping, recovery) are
  **out of Run 0.5 scope** and remain to be calibrated after these two upstream controls are settled.
